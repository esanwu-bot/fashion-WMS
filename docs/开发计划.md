# RFID 服装零售 WMS · 开发计划

> 版本 v1.0 · 2026-10-06 · 前置阅读：`项目需求.md`、`技术选型.md`
> 总周期 **12 周** 到试点上线（1 总仓 + 3 门店），后接 4 周推广期。人力假设：后端 2、前端 1.5、PDA 0.5、测试 1、实施/硬件 0.5。

---

## 1. 排期原则

1. **硬件是唯一不可压缩的关键路径。** 因此所有 RFID 功能先对 **模拟设备适配器（sim driver）** 开发验收，真机到货后只做联调（见 `技术选型.md §2`），不允许"设备等软件"或"软件等设备"。
2. **契约先行。** 每个模块开工前，接口路径 + 请求/响应结构 + 错误码先冻结写入 `接口设计.md`，前端与后端同日可并行开工。
3. **库表先于业务。** `schema.sql` 在 M0 末冻结 v1，后续变更走 migration 并同步更新 ER 文档。
4. **每个里程碑必须可演示。** DoD 是"在演示环境跑通一条端到端链路"，不是"代码写完了"。
5. P0 功能不达标不进下一里程碑；P1 可顺延到推广期。

## 3. 任务分解（WBS）

### M0（W1）· 骨架
- 后端：TP8 多应用初始化、统一响应/异常处理、JWT 中间件、validate 规范、think-queue + Redis、migration、日志结构化
- 前端：复用 React 脚手架改造（路由/请求层/表格范式/主题对齐原型配色）、登录页与侧栏 6 菜单
- DB：`schema.sql` v1 + `数据库ER.md`（本次交付已含）
- DevOps：Docker Compose（php-fpm/nginx/mysql5.7/redis/worker/cron）、GitHub Actions（lint+phpstan+phpunit+前端 build）
- 设备：`sim` 驱动契约定义（统一读取事件 JSON）、`php think rfid:sim` 命令

### M1（W2–W3）· 主数据与发码
| 任务 | 负责 | 人日 |
|---|---|---|
| SPU/SKU/颜色/尺码/品类/季节波段 CRUD + 字典 | 后端A | 3 |
| 色码矩阵生成与批量建 SKU（含编码规则、冲突检测） | 后端A | 3 |
| EPC 规则（96bit 分段/掩码/序列号池）+ 发码服务 | 后端B | 4 |
| 打印任务队列 + 打印机适配（sim/real）+ 回执 | 后端B | 3 |
| Excel 导入（模板/校验/逐行错误报告）与导出 | 后端A | 2 |
| 矩阵弹窗 UI + 商品列表 + 导入向导 | 前端 | 5 |
| 单元测试（Service 层发码/矩阵） | 全员 | 2 |

### M2（W4–W5）· 通道门入库
| 任务 | 负责 | 人日 |
|---|---|---|
| ASN/收货单模型与状态机、单号服务 | 后端A | 3 |
| `POST /device/read` 接收 + Stream 入队（P95 < 80ms） | 后端B | 3 |

| 联调：`rfid:sim --miss=2` 全链路 | 测试 | 2 |

### M3（W6–W7）· 库存与盘点
- 库存台账/流水/EPC 明细查询（后端A，4）
- 盘点任务模型 + 下发 PDA + 盲盘回传（后端B，4）
- 差异计算、复盘、审核生成盈亏调整单（后端A，3）
- 雷达找货（RSSI 上报 + 定位提示，后端B，2）
- PDA：盘点执行页（NativeScript，PDA0.5，4）
- Web：盘点列表 + 进度条 + 差异表（前端，5）
- 离线补传与幂等验证（测试，3）

### M4（W8–W9）· 分拣与出库
- 波次服务（按目标聚合、锁定库存）（后端A，4）
- 分拣墙格口分配 + 灯光指令队列 + 扫描防错（后端B，4）
- 通道门复核与装车发货（后端A，3）
- EPC 归属转移与在途账（后端B，2）
- Web：分拣墙 12 格口实时页 + 波次表（前端，6）
- PDA：拣货执行（顺延 P1）

### M5（W10）· 门店协同
- 调拨单 + 门店收货（后端A，3）
- 缺码预警计算（定时 + 触发式）与补货任务（后端B，2）
- 退换货解绑/重绑 + 次品退仓（后端A，3）
- 门店 PDA 收货/找货/打烊盘（PDA，4）
- Web 门店协同页（前端，4）

### M6（W11）· 看板/权限/压测
- 看板聚合服务 + 缓存 + 对账 SQL（后端A，3）
- RBAC 数据范围拦截 + 操作日志检索（后端B，2）

- 看板页 + 设备状态表（前端，4）
- 回归 + 缺陷收敛（测试，5）

### M7（W12）· 上线

- 部署（stage→prod）、备份与回滚预案演练
- 培训 2 场（仓库作业 / 门店店长），SOP 文档
- 灰度试运行 1 周：真实 ASN ≥ 5 单、门店打烊盘 ≥ 3 天

## 5. 测试与质量策略

| 层次 | 手段 | 门禁 |
|---|---|---|
| 单元测试 | phpunit + mockery，覆盖 Service（发码、库存、差异、状态机、权限） | 增量覆盖率 ≥ 60%，库存与发码模块 ≥ 80% |
| 接口测试 | Apifox/Postman 集合（与 `接口设计.md` 一一对应），CI 跑关键链路 | P0 用例 100% 通过 |
| RFID 专项 | ① 漏读率：固定 500 件过门 10 次统计；② 串读：邻门同时作业；③ 去重：同 EPC 窗口内重复上报；④ 离线补传断点续传 | 漏读率 ≤ 0.2%，重复读取不重复计库 |
| 性能 | k6：4 门并发 2400 EPC/min 30 分钟；列表接口 1.24M EPC 数据量 P95 | 上报 P95 < 80ms，列表 P95 < 500ms，队列无积压 |
| 数据一致性 | 对账脚本：`SUM(流水) == 库存数量`、`EPC 状态 == 库存归属` | 每日跑，差异为 0 |
| 回归 | 每里程碑末执行 P0 全链路脚本（收货→盘点→分拣→出库→门店收货→退货） | 无 P0/P1 缺陷 |
| UAT | 客户按 `项目需求.md §12` 逐条签字 | DoD 全绿 |

缺陷分级：P0 阻断上线（当天修）、P1 里程碑内修、P2 推广期修、P3 记录。

## 6. 工程流程

- 分支：`main`（可发布）/ `dev`（集成）/ `feat/M2-asn-tunnel`（短生命周期，≤3 天）；PR 需 1 人评审 + CI 绿。
- 提交规范：Conventional Commits（`feat(inbound): ...`）。
- 每周一 30 分钟站会对齐里程碑出口条件；每里程碑末 1 次演示会（客户参加，必须现场看真机/模拟器操作）。
- 文档随代码走：`schema.sql`、`数据库ER.md`、`接口设计.md` 是活文档，改动同 PR 更新。
- 需求变更走"变更单"：影响 P0 出口条件或里程碑日期的，必须重排期并记录在 `待办清单`。
