## 1. 项目背景与目标

服装零售行业的库存管理长期存在三个痛点：**入库清点慢**（人工逐件扫码，整箱到货核对耗时）、**盘点失真**（抽盘/目视盘点差异大、周期长）、**尺码断码看不见**（同款不同色不同码，缺货往往是"某个码没了"而不是"这款没了"）。

本项目以 **RFID UHF（超高频）单品级标签** 为数据底座，构建覆盖 **总仓 → 分拣 → 门店** 的 WMS：每一件衣服在出厂/入库前绑定唯一 EPC 码，之后所有的过门读取、盘点挥扫、分拣亮灯、找货定位、销售核销都围绕这个 EPC 展开，形成单品全生命周期追踪。

### 1.1 业务目标（可量化）

| 编号 | 目标 | 基线（人工/条码） | 目标值 | 度量口径 |
|---|---|---|---|---|
| G-01 | 整箱入库效率 | 8~12 分钟/托 | ≤ 60 秒/托 | 通道门读取时长 |
| G-02 | 单店盘点耗时 | 4~6 小时/店 | ≤ 15 分钟/店 | PDA 挥扫起止时间 |
| G-03 | 盘点准确率 | 92%~96% | ≥ 99.9% | 盘点差异件数 / 账面件数 |
| G-04 | 分拣错分率 | 3‰~8‰ | ≤ 0.5‰ | 分拣墙防错报警数 / 分拣件数 |
| G-05 | 断码响应时间 | 次日 | ≤ 10 分钟 | 缺码预警触发到补货任务生成 |
| G-06 | 找货耗时 | 5~20 分钟 | ≤ 60 秒 | 雷达找货锁定时间 |

原型中的看板数据即为目标形态：**今日入库 45,280 件、今日出库 38,120 件、活跃 EPC 1.24M、盘点准确率 99.98%、IoT 设备在线 42/45**。

### 1.2 系统定位

- **是**：RFID 作业执行系统 + 库存真相源（Inventory System of Record）+ 设备接入与数据中台。
- **不是**：POS 收银系统、ERP 财务系统、生产 MES、电商平台。这些数据通过接口进入或流出本系统（见 §9）。

## 3. 核心业务流程（端到端）

```
① 主数据：SPU → 色码矩阵 → SKU → EPC 规则
② 发码：按 SKU 计划量下发标签打印任务 → 打印/写入 EPC → EPC 绑定 SKU（状态：已绑定）
③ 入库：ASN 预约 → 整箱推过通道门 → 批量读取 EPC → 与 ASN 比对 → 差异报警 → 上架到库位
④ 库存：EPC 位置/状态实时更新；移库、冻结、库存流水记账
⑤ 盘点：按区域建任务 → PDA/盘点车挥扫 → 实盘 vs 账面 → 差异审核 → 盈亏调整
⑥ 出库：订单/调拨生成波次 → 拣货 → 分拣墙逐件扫描亮灯（错分报警）→ 复核 → 装车发货
⑦ 门店：调拨在途 → 门店 PDA 收货 → 陈列/后仓库存 → 缺码补货 → 销售/试衣间数据
⑧ 逆向：顾客退货质检 → 重新绑定 EPC 上架 或 解绑退回总仓次品区
⑨ 反馈：看板 KPI、盘点准确率、设备在线率、读取量统计
```

关键约束：**EPC 全局唯一且一次绑定一生追踪**。任何一次读取都要能回答"哪个设备、什么时间、读到哪个 EPC、属于哪个单据"，否则差异无法追溯。

## 5. RFID 专项需求（区别于普通 WMS 的部分）

| 编号 | 需求 | 说明 |
|---|---|---|
| RF-01 | EPC 结构 | Gen2 96bit：Header(8) + TMF(28) + RFI/公司码 + 序列号；库表按 24 位十六进制字符串存储，唯一索引 |
| RF-02 | 绑定唯一性 | 一个 EPC 同一时刻只能绑定一个 SKU 与一个库存归属；解绑后方可复用（复用需审批与留痕） |
| RF-03 | EPC 生命周期状态 | `待写入 → 已绑定 → 在库 → 上架 → 波次锁定 → 已出库/在途 → 门店在库 → 已销售 / 已退货 / 已解绑 / 报废 / 盘亏遗失` |
| RF-04 | 漏读抑制 | 过门读取需满足"读取时长 + 双天线确认"；低于阈值提示补扫；漏读率纳入设备统计 |
| RF-05 | 误读抑制 | 通道门读取过滤非本单据 EPC（邻门串读）→ 归入异常件；RSSI 门限可配 |
| RF-06 | 去重策略 | 同一次作业窗口内同一 EPC 多次读取按一次计（窗口时长可配，默认 3s） |
| RF-07 | 离线容灾 | PDA 断网本地 SQLite 缓存读取结果，复网批量补传，服务端幂等去重 |
| RF-08 | 高并发写入 | 单门峰值 ≥ 600 EPC/分钟，4 门并发 ≥ 2400/分钟，入库不阻塞界面（走队列） |
| RF-09 | 金属/液体衰减应对 | 吊牌/洗水唛标签选型建议进入实施规范（文档 §风险） |
| RF-10 | 数据量 | 按 1.24M 活跃 EPC、日增 5 万、原始读取日志日增 500 万条估算，需分区/归档策略 |

## 7. 关键业务规则（开发必须实现，测试必须覆盖）

1. **差异容差**：通道门实读 < 预期 → 差异报警且不允许直接完成收货；实读 > 预期（串读/夹带）→ 异常件列表待归属。默认零容差，可按供应商配置 ±N 件容差。
2. **盘点准确率** = `命中 SKU 数 / 应盘 SKU 数`，按 SKU 存在性口径统计（原型显示 99.98%）。
3. **可售库存** = 在库数量 − 波次锁定 − 冻结 − 次品。缺码判定基于可售库存 = 0。
4. **分拣墙防错**：扫描 EPC 所属波次的目标门店/订单与投入格口不一致 → 报警且不计数，格口状态置 `error`。
5. **所有权转移**：调拨/出库发货后 `epc.owner_type/owner_id` 从仓库变为门店；门店收货确认后库存才计入门店。
6. **退货重绑**：无损退货必须先解绑旧 EPC（旧码进 `已解绑`）再绑新 EPC；同一 EPC 原码复用需主管审批。
7. **EPC 唯一约束**：数据库层唯一索引，任何写入冲突返回业务错误码，不允许静默覆盖。
8. **单据状态机**：所有单据状态变更走服务端校验（前置状态白名单），禁止前端直接改状态字段。
9. **幂等去重窗口**：同一设备同一 EPC 在窗口期内的重复读取只生成一条库存事件。
10. **在途不入账**：调拨发出后计入"在途"，接收方确认后才转入目标方在库，避免双记。

## 11. 假设、约束与风险

### 假设
- 单仓 + 若干门店规模（≤ 50 家门店，1 个总仓），日出入库 ≤ 5 万件。
- 硬件由客户提供或指定品牌型号，标签选型已验证可用。
- ERP/POS 具备可用的对接接口或导出能力。

### 约束
- 数据库沿用本地 **MySQL 5.7**：DDL 不能使用 `CHECK` 约束（5.7 解析但不生效）、需 `utf8mb4` + `ROW_FORMAT=DYNAMIC`、长字符串索引前缀控制在 191 字符内。
- 后端 PHP 8.3，团队既有栈为 ThinkPHP（详见 `技术选型.md`）。

### 风险清单

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 硬件到位与调试周期不可控（通道门/分拣墙/标签） | 关键路径延误 | 里程碑前 2 周锁定采购；软件先用模拟设备适配器开发（见 §12） |
| R2 | 金属/液体环境漏读 | 收货差异、盘不准 | 标签选型测试 + 双天线 + 补扫流程 + 漏读率纳入设备统计 |
| R3 | EPC 串读（邻门/邻箱） | 库存归属错 | RSSI 门限 + 单据白名单 + 异常件人工归属 |
| R4 | 原始读取日志暴涨 | 存储与查询压力 | 分区/冷热分层，90 天归档，统计走日汇总表 |

## 12. 验收标准（Definition of Done）

功能层面：

1. 通道门在 **模拟设备适配器** 与 **真实设备** 两种模式下均能完成"500 件 ASN 实读 498 → 报警 → 差异处理 → 完成收货 → 库存与流水一致"全流程。
2. 分拣墙能完成"扫描 → 正确格口亮灯 → 错格口报警 → 复核件数一致 → 波次状态推进"。
3. 盘点任务从新建 → 下发 PDA → 盲盘回传 → 差异表 → 审核生成盈亏调整 → 库存更新，且准确率在看板正确反映。
4. 门店调拨发出/收货后 EPC 归属与双方库存正确，无在途双记。
5. 退换货"解绑 → 重绑上架"与"解绑 → 退回总仓次品区"两条链路可演示且有审计留痕。
6. 权限：仓库人员不可见其它仓库数据；关键审批动作需主管角色。
7. 所有 P0 接口具备自动化用例（`接口设计.md` 对应集合），后端服务层单测覆盖率 ≥ 60%。

非功能层面：

8. 4 门并发 2400 EPC/分钟压测 30 分钟无积压、无丢失、P95 上报延迟 < 80ms。
9. 关键列表接口 P95 < 500ms（1.24M EPC 数据量下）。
10. 操作日志覆盖所有写操作，可检索导出。
