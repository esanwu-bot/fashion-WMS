# RFID 服装零售 WMS · 接口设计

> 版本 v1.0 · 2026-10-06 · 状态：待评审冻结（M0 末 v1 冻结，之后走变更评审）
> 前置阅读：`项目需求.md`（需求编号）、`技术选型.md`（框架与设备接入架构）、`schema.sql`（字段权威来源）
> 覆盖范围：后端对外的全部 HTTP 接口（Web 后台 / PDA 门店端 / RFID 设备 / 外部系统），共 **161 个接口条目**（P0 98 · P1 56 · P2 7；合并型 CRUD 行展开后约 200 个端点）。
> 开发期一律可用 **模拟设备适配器**（`sim` driver）打通全部链路的接口契约，无需等硬件（风险 R1 应对）。

## 1. 全局约定

### 1.1 应用边界与 Base URL

后端为单应用多模块（`think-multi-app`），按**鉴权与限流边界**拆四个入口，路径前缀即应用名：

| 应用 | Base URL | 调用方 | 鉴权方式 | 限流 | 说明 |
|---|---|---|---|---|---|
| `admin` | `/api/v1/admin` | Web 管理后台（React） | 用户 JWT | 600 req/min·user | 管理、作业面板、看板、报表 |
| `store` | `/api/v1/store` | PDA / 门店端（NativeScript） | 用户 JWT（`user_type=pda/store`） | 300 req/min·user | 面向移动端的精简接口，支持批量补传 |
| `device` | `/api/v1/device` | 通道门/桌面机/PDA 采集服务/分拣墙控制板/打印机 | **设备 token**（`X-Device-Token`） | 200 req/min·device | 只接受设备凭证，不接受用户 JWT；P95 < 80ms |
| `open` | `/api/v1/open` | ERP / POS / OMS / 物流 | AppKey + HMAC-SHA256 签名 | 100 req/min·app | 入向主数据、销售；出向轨迹回调 |

- 开发环境 `http://127.0.0.1:8000`，生产 `https://{host}`（全链路 HTTPS，PDA 走 4G 同样强制 TLS）。
- 版本只体现在路径（`v1`）。破坏性变更前开 `v2` 并保留 `v1` 一个季度；兼容性变更（新增字段/新增枚举值）不升版本。
- 时间：请求与响应统一 `datetime` 字符串 `YYYY-MM-DD HH:mm:ss`（Asia/Shanghai，无时区后缀）；毫秒精度字段（`read_time`、`started_at`）按需用 `YYYY-MM-DD HH:mm:ss.SSS`。日期区间用 `YYYY-MM-DD`。
- 数量单位为**件**（`int`），金额为 `decimal(12,2)` 字符串或数字（前端展示用 `Number`，禁止参与计算链路）。
- 空值：无值返回 `null`，不返回空字符串占位；集合类返回 `[]`。
- ID 一律 `bigint`，JSON 中以**字符串**传输（避免 JS 精度丢失），入参同理接受字符串。

### 1.2 统一响应信封

沿用现有脚手架的字段名（`code / message / data / timestamp`），并做**一处归一化调整**：成功码由历史项目的 `200` 改为 `0`，业务错误改用 6 位域码（见 §1.3）。前端只需在响应拦截器里判断 `code === 0`，其余按 HTTP 状态兜底。

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "trace_id": "a1b2c3d4e5f60718",
  "timestamp": 1791676800
}
```

失败响应（含字段级校验细节，供表单定位）：

```json
{
  "code": 60003,
  "message": "衣物不属于此格口目标订单，请检查！",
  "data": null,
  "errors": [
    { "field": "cell_no", "message": "应投格口 05(GZ-01)，实投 03(BJ-01)" }
  ],
  "trace_id": "a1b2c3d4e5f60719",
  "timestamp": 1791676801
}
```

约定：

- HTTP 状态与 `code` 分工：**HTTP 表达传输层语义**（200 业务成功、201 创建成功、202 已入队、400/401/403/404/409/422/429/500/503），**`code` 表达业务语义**。前端一律先读 `code`。
- `data` 为对象或数组；列表接口固定 `data.list + data.total`（见 §1.6）。
- `trace_id`：每个请求生成（`sys_operation_log.trace_id` 与结构化日志同值），排障时以此为唯一线索。设备上报接口必须回传 `trace_id`，便于对齐"这次过门为什么少 2 件"。
- `message` 为可直接展示的中文短语，不含堆栈；技术细节进日志。
- 写接口成功但**只入队未处理完**时返回 `202`，`data.process_status = "pending"`，由调用方轮询或等回调（见 §13）。

### 1.4 鉴权

**用户侧（admin / store）**

```
Authorization: Bearer <access_token>
```

- Access Token 2h，Refresh Token 7d；`POST /api/v1/admin/auth/refresh` 换发，旧 refresh 一次一用（旋转）。
- Payload：`{ uid, username, user_type, warehouse_id, store_id, role_codes[], scope, jti, iat, exp }`。
- **数据范围（FR-SYS-02）**：中间件按 `scope` = `all` / `warehouse:{id}` / `store:{id}` 自动注入查询条件。接口**不接受**前端传入的"跨范围"参数；越权返回 10007。
- 单点踢出：Redis 记 `user:token_ver:{uid}`（登录时自增，`schema.sql` 不落列），JWT 携带 `kv`，与 Redis 值不匹配即 10004；禁用用户时同步自增，实现"禁用即时失效"（FR-SYS-01）。

**设备侧（device）**

```
X-Device-Code: GATE-A01
X-Device-Token: <台账生成的 token>
X-Device-Ts: 1791676800
X-Device-Sign: HMAC-SHA256(device_code + ts + body_md5, token)
```

- token 明文只在生成时返回一次，台账存哈希。
- 设备 token 只能访问 `device` 应用；用户 JWT 不能访问 `device` 的写入接口（PDA 采集服务例外，见 §6.5）。

### 1.5 幂等

| 场景 | 幂等键 | 载体 | 落库 |
|---|---|---|---|
| 所有写接口（admin/store/open） | `X-Request-Id`（客户端 UUID） | Header | `sys_idempotency`（`scope_type=user`，保留 24h） |
| 设备读取上报 | `batch_no`（`{device_code}-{yyyyMMddHHmmss}-{seq}`） | Body | `rfid_read_batch.uk_batch_no` |
| 库存流水 | `{biz_type}:{biz_id}:{sku_id\|epc}:{direction}:{stock_type}` | Service 组装 | `inv_transaction.dedup_key` 唯一索引 |
| PDA 离线补传 | 客户端本地 UUID + 同一 `batch_no` | Header + Body | 重放返回首次响应快照（10101） |

重放行为：**命中已存在的幂等键时，返回首次响应的 `result_body` 快照 + HTTP 200 + `code=10101`**，绝不重复执行副作用。库存、EPC 状态、发货等"必须只生效一次"的动作全部依赖此机制（风险 R6 应对）。

### 1.6 列表、分页、排序、筛选

```
GET /api/v1/admin/inventory/stocks?page=1&page_size=20
    &sort=updated_at:desc,sku_code:asc
    &owner_type=warehouse&owner_id=1
    &stock_type=normal
    &keyword=AW26-JK
    &created_at_start=2026-10-01&created_at_end=2026-10-06
```

| 参数 | 规则 |
|---|---|
| `page` / `page_size` | 默认 `1` / `20`；`page_size` 上限 `200`（导出走异步任务，不受限） |
| `sort` | `字段:asc\|desc`，逗号分隔，最多 3 项；字段必须在白名单内，否则 10201 |
| `keyword` | 模糊匹配编码+名称（后端按表指定列，不任意拼 LIKE） |
| `*_start` / `*_end` | 时间/日期区间，左闭右开 |
| 多值 | `status=a,b,c` 表示 IN |
| 汇总 | 允许返回 `data.summary`（如合计件数），与分页解耦（全筛选条件下的合计，非当前页合计） |

```json
{
  "code": 0, "message": "success",
  "data": {
    "list": [ { } ],
    "total": 1248, "page": 1, "page_size": 20,
    "summary": { "qty": 45280, "amount": 1284500.00 }
  },
  "trace_id": "..."
}
```

### 1.7 命名与风格

- 路径：`/api/v1/{app}/{domain}/{resource}`，资源用**复数名词**、kebab-case；动作型子路径用动词（`/{id}/confirm`、`/reset`、`/dispatch`）。
- JSON 字段：`snake_case`，与 `schema.sql` 列名保持一致（后端直接返回模型数组，零映射成本；前端 TS 类型同名生成）。
- 枚举值：与 schema 注释完全一致的小写英文（如 `diff_pending`、`wave_locked`），中文文案由前端字典渲染，**接口不返回中文状态**。
- 时间字段：`*_at`（datetime）、`*_time`（业务时间）、`*_date`（date）。
- 数量字段：`*_qty`（件数）、`*_count`（次数/条目数）。
- 写接口的请求体使用**扁平结构 + 明细数组**（`items: []`），不做无谓嵌套。

### 1.8 审计与脱敏

- 所有非 GET 接口经 `sys_operation_log` 中间件落库：`module/action/biz_type/biz_id/url/params(脱敏)/before_data/after_data/ip/result/duration_ms/trace_id`。
- 敏感字段（`password`、`auth_token`、手机号、`driver_phone`）在 `params` 与导出文件中掩码（`138****8000`）。
- 库存调整、差异处理、EPC 解绑/重绑、盈亏审核四类动作**必须**写 `before_data/after_data`。

### 6.2 详解 · 读取上报（本契约的核心）

`POST /api/v1/device/read`

```json
{
  "device_code": "GATE-A01",
  "batch_no": "GATE-A01-20261003104118-0001",
  "scene": "gate",
  "biz_type": "receipt",
  "biz_id": "6621",
  "started_at": "2026-10-03 10:41:12.120",
  "finished_at": "2026-10-03 10:41:18.030",
  "antenna_mode": "dual",
  "tags": [
    { "epc": "300406941234567890ABCDEF01", "rssi": -52, "antenna_no": 1, "read_count": 7,
      "first_read_at": "2026-10-03 10:41:13.045", "phase": 128.4 },
    { "epc": "300406941234567890ABCDEF02", "rssi": -61, "antenna_no": 2, "read_count": 3,
      "first_read_at": "2026-10-03 10:41:14.210", "phase": null }
  ]
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `batch_no` | ✅ | 设备侧生成，全局唯一（幂等键）；重复上报 → 直接返回首次快照（10101） |
| `scene` | ✅ | `gate/desktop/pda/sortwall/fitting/printer`，须与 `dev_device.device_type` 匹配（30004） |
| `biz_type` | ✅ | `asn/receipt/stocktake/sort/check/store_receive/find/scrap`；`biz_id` 指向对应单据 |
| `tags[].epc` | ✅ | 长度按规则校验（20102）；无档 EPC 不拒收，计入 `unknown_count` |
| `tags[]` 条数 | ✅ | ≤ 2000（超出 30005）；大托/大批请分批并使用同一 `batch_no` 前缀 + 递增 `seq` |
| `rssi` | ⬜ | 低于设备 `rssi_min` 门限的条目在服务端标记为疑似串读（RF-05） |

响应（HTTP 202，处理是异步的）：

```json
{ "code": 0, "message": "accepted",
  "data": { "batch_no": "GATE-A01-20261003104118-0001", "process_status": "pending",
            "raw_count": 498, "estimated_finish_ms": 900 },
  "trace_id": "dev-a1b2c3" }
```

**服务端处理顺序（`readlog` 队列消费者）**：
1. 落 `rfid_read_batch`（`raw_count`）+ 原始明细落 `rfid_read_log`；
2. 按设备 `dedup_window_s`（默认 3s）去重 → `distinct_count` / `dup_count`；
3. 解析 EPC → `sku_id`；无档记 `unknown_count`；
4. 按 `biz_id` 白名单比对：非本单据 EPC 记 `stray_count`（同时写 `in_discrepancy(diff_type=stray)` 或 `out_sort_record(result=unknown)`）；
5. 归集到单据明细（`in_receipt_item` / `cnt_record` / `out_sort_record`）；
6. 触发库存事件（`stock` 队列，仅"确认类"动作才记账，过门本身不记账 —— 见 §7.3）；
7. `process_status = done`，异常则 `failed` + `process_msg`。

## 14. 单据状态机与接口白名单

> 业务规则 8：状态只能由服务端按白名单推进。**接口不接受前端直接传 `status` 字段**（PATCH 类动作接口除外，且动作即语义）。

| 单据 | 当前态 | 允许接口 | 目标态 |
|---|---|---|---|
| ASN `in_asn` | `appointed` | `start-gate` | `waiting_gate` → `receiving` |
| | `receiving` | `stop-gate`（有差异） | `diff_pending` |
| | `receiving` / `diff_pending` | `confirm` | `completed` |
| | `appointed` / `waiting_gate` | `cancel` / `PUT` | `cancelled` / 不变 |
| 收货单 `in_receipt` | `scanning` | `stop-gate` | `diff`（有差异）或 `confirmed` 前置 |
| | `diff` | `discrepancies/{id}/handle` 全部处理 | `confirmed` |
| | `confirmed` | `confirm` | `completed`（终态） |
| 差异单 `in_discrepancy` | `pending` | `handle(rescan/partial/hold)` | `processing` / `resolved` / `ignored` |
| 盘点任务 `cnt_task` | `pending` | `dispatch` / `start` | `counting` |
| | `counting` | `finish` | `done` |
| | `done` | `recount` | `recount` |
| | `done` / `recount` | `audit` | `audited`（生成调整单） |
| 调整单 `cnt_adjust` | `pending` | `approve` | `approved` |
| | `approved` | `post` | `posted`（终态；重复过账 → 50007） |
| 出库单 `out_order` | `pending` | `POST /waves` | `waved` |
| | `waved` | 拣货/分拣/复核推进 | `picking` → `sorting` → `checking` → `ready` |
| | `ready` | `depart` | `shipped` |
| | `shipped` | 门店收货完成 | `received` |
| | ≤ `checking` | `cancel` | `cancelled`（回滚锁定与 EPC 状态） |
| 波次 `out_wave` | `planned`→`shipped` | 同上，`release` 仅在 `planned/picking` | 见 `schema.sql` |
| 复核单 `out_check` | `pending`/`checking` | 过门读取 | `checking` |
| | `checking` | `pass` | `passed` → 允许装车；差异未处理 → `blocked` |
| 调拨 `st_transfer` | `pending` | `depart` | `shipped` → `in_transit` |
| | `arrived` | `receive` | `received`（差异则 `diff`） |
| EPC `rfid_tag` | `pending_write`→`bound`→`in_stock`→`put_away`→`wave_locked`→`checking`→`in_transit`→`store_stock`→`sold`/`returned`/`unbound`/`scrapped`/`lost` | 由各作业接口驱动，禁止手工跳转 | RF-03 |

非法跳转一律返回对应状态错误（40001/50004/60001/60006/70001…），且 `sys_operation_log` 记录 `result=fail`。

## 15. 实时性与调用序列

### 15.1 轮询 / SSE 约定

### 15.2 关键链路时序

**通道门入库（DoD #1）**

```

Web  POST /inbound/discrepancies/7712/handle(partial)

PDA  GET  /inbound/putaway-tasks → POST /{id}/done → 库位落位
```

**盘点（DoD #3）**

```
Web   POST /count/tasks → POST /count/tasks/{id}/dispatch → "已下发盘点任务至 PDA-05"
PDA   GET /store/count/tasks → start → (挥扫) POST /device/read ×N（离线时本地缓存 batch_no）

看板  accuracy 取自任务快照，与报表 rpt_daily_owner 一致
```

**分拣与出库（DoD #2）**

```
Web   POST /outbound/waves (order_ids)            → 锁定库存, wave=planned
Web   POST /sort-walls/2/bind-wave (wave_id)      → 12 格口分配目标

门店  POST /store/transfers/{id}/receive          → 归属转移, 门店在库+, EPC=store_stock
```

**退货重绑（DoD #5）**

```
PDA   POST /store/returns → GET /store/returns/{id}
PDA   POST /store/returns/{id}/inspect (good→rebind / defect→return_wh)
```
